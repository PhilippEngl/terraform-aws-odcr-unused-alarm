# terraform-aws-odcr-unused-alarm

A Terraform module that alarms when EC2 On-Demand Capacity Reservations sit unused. An unused slot in a reservation is billed at the On-Demand rate whether anything runs in it or not, so an idle reservation is money spent on capacity nobody gets.

The case it was written for: a **targeted** reservation next to running On-Demand instances of the same type, AZ and placement group. An instance with `capacityReservationPreference = open` only uses **open** reservations, so the instances run On-Demand beside the idle slots and nothing reports it. The alarm makes that visible within hours; the fix is to name the reservation, or a Capacity Reservation group, in the launch template.

## What it creates

- **CloudWatch alarms on `AWS/EC2CapacityReservations` `AvailableInstanceCount`**, at any of three scopes:
  - one per Capacity Reservation ID, which names the idle reservation;
  - one per instance type, which also covers reservations created later;
  - one account-wide alarm on the dimensionless metric, which covers everything in the account and region.
- An **SNS topic** with a policy that lets CloudWatch and EventBridge in this account publish, plus optional email subscriptions. Or bring your own topic.
- Optionally, an **EventBridge rule** forwarding AWS Health's `AWS_EC2_ODCR_UNDERUTILIZATION_NOTIFICATION` and `…_SUMMARY` events to the same topic.

## How the alarm decides

Each alarm uses the `Minimum` of `AvailableInstanceCount` over one-hour periods, and fires when every one of the last `evaluation_hours` periods (default 6) is above `unused_threshold` (default 0). A slot has to be unused for a whole hour, six hours running, before anyone is paged. A rolling node group replacement frees a slot for minutes and does not count.

`treat_missing_data` defaults to `notBreaching`, because a cancelled or expired reservation stops publishing and its alarm should settle in OK.

## Alarms and Health events are complementary

AWS Health sends its underutilization events only below **20 percent** utilization. A reservation with 2 of 3 slots used is at 67 percent and never produces one, while the alarm fires for its idle slot. The Health events add coverage of reservations nobody listed, at no per-reservation cost. They already go to the owning account's email address; `create_health_event_rule` routes them to the topic as well.

## Requirements

Terraform >= 1.9 and the AWS provider >= 6.0. Terraform 1.9 because `sns_topic_arn` validates against `create_sns_topic`, which needs cross-object references in `validation` blocks.

Two things the module cannot check for you:

1. **The region.** Capacity Reservation metrics and AWS Health events are regional. Apply the module once per region that holds reservations, with a provider for that region.
2. **The account.** Metrics are per account. An organisation with reservations in several accounts needs one instance of the module per account, for example through a provider alias per account or CloudFormation StackSets.

## Usage

```hcl
module "odcr_unused_alarm" {
  source = "github.com/your-org/terraform-aws-odcr-unused-alarm"

  name_prefix = "capacity"

  capacity_reservation_ids = ["cr-0123456789abcdef0", "cr-0123456789abcdef1"]
  instance_types           = ["m8id.16xlarge"]

  email_subscriptions = ["capacity-team@example.com"]
}
```

[`examples/targeted-odcrs`](examples/targeted-odcrs) is the worked example, with placeholder reservation IDs.

### Using an existing topic

```hcl
create_sns_topic = false
sns_topic_arn    = "arn:aws:sns:eu-central-1:111122223333:ops-alerts"
```

That topic's policy must already allow `cloudwatch.amazonaws.com` to publish, and `events.amazonaws.com` too if `create_health_event_rule` is true. The module does not change a topic it did not create.
